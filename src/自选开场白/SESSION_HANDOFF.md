# 自选开场白：本轮交接记录

## 当前结论

第一阶段原型已经能在 SillyTavern 第 0 楼中正常渲染。当前内容只验证交互能力，不是正式产品规范，也没有绑定正式角色卡的 MVU 结构、世界书条目或生成流程。

已在实际页面确认以下链路可用：

1. 消息正文中的 `<自选开场白/>` 被角色局部正则命中。
2. 酒馆助手创建 `TH-message--0--0` iframe。
3. iframe 从 `http://localhost:5500/dist/自选开场白/index.html` 加载编译产物。
4. Vue 成功挂载到 `#app`，显示四步开场白原型。
5. `pnpm watch` 编译后能通过端口 `6621` 向酒馆推送更新。

## 本轮发现并解决的问题

### 1. `transport error` / WebSocket 错误

原因：`pnpm watch` 未运行，端口 `6621` 没有监听。

处理：启动 `pnpm watch`。日志出现“成功连接到酒馆网页”后恢复。

注意：`pnpm sync` 是另一套世界书/角色卡同步命令，不是本前端的实时编译监听命令。

### 2. 正则开启后第 0 楼变成空白

第一层原因：最初端口 `5500` 由 `python -m http.server` 提供。文件虽然返回 200，但没有 `Access-Control-Allow-Origin`，导致 iframe 内的 jQuery `.load()` 被跨域策略拦截。

处理：换成 `http-server --cors`。验证响应为 200 且 `Access-Control-Allow-Origin: *`。

第二层原因：跨域修复后，编译产物已经进入 iframe，`#app` 也存在，但入口代码在挂载 Vue 前无限等待消息楼层出现 `stat_data`。当前原型没有正式 MVU 适配器，因此该字段可能永远不存在。

处理：从 `index.ts` 移除渲染前的 `stat_data` 强制等待。当前演示立即挂载，未来正式 MVU 初始化由 `integration.ts` 中的角色卡适配器负责。

### 3. 关于角色名 `111`

`111` 是本轮临时角色卡名称，不是第 0 楼正文。第 0 楼真实触发内容是 `<自选开场白/>`。后续诊断不要再用角色名推断消息正文，应直接检查消息编辑框、正则替换产物和 `TH-message-*` iframe。
